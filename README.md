# สรรพวาทิต — ระบบบริหารจัดการชมรมดนตรีไทย โรงเรียนสรรพวิทยาคม

รุ่น 1.0 (ขั้นที่ 1): ล็อกอิน · ทะเบียนสมาชิก · ตำแหน่งและสิทธิ์ · รอบซ้อม · ที่ปรึกษา · แผนผัง · ระดับฝีมือ · ส่งออกบอร์ด/แผนผัง/รายชื่อ

PWA แบบ static ไม่มี build step (HTML + CSS + Vanilla JS) โครงเดียวกับระบบ Mae Sot Musicology

## ลองใช้ทันที (โหมดสาธิต)

ยังไม่ต้องมี Firebase: เปิด `index.html` ผ่านเว็บเซิร์ฟเวอร์ (หรืออัปขึ้น GitHub Pages) แล้วกดเข้าสู่ระบบ ระบบจะให้เลือกบัญชีสมมติ (ครู ประธาน รองประธาน เหรัญญิก เลขานุการ กรรมการ) ข้อมูลเก็บในเบราว์เซอร์นั้นเท่านั้น

เมื่อใส่ค่า Firebase จริงแล้ว ยังเข้าโหมดสาธิตได้ด้วย `index.html?demo=1` และออกด้วย `?demo=0`

## ไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `config.js` | ค่า Firebase, อีเมลครูคนแรก, โดเมนอีเมล, ตำแหน่ง, ประเภทสมาชิก, ระดับฝีมือ, เครื่องดนตรี |
| `core.js` (`window.MC`) | ตัวช่วย, modal/toast, ย่อรูป, ส่งออก PDF/PNG, ตัวเขียน DOCX, ตรวจขนาดจอ |
| `backend.js` (`window.B`) | ชั้นข้อมูล: Firebase / โหมดสาธิต, outbox ออฟไลน์ (ปรับจากระบบเดิม) |
| `app.js` | หน้าจอและการทำงานทั้งหมด (view + ตาราง `ACT`) |
| `style.css` | ธีมม่วงเปลือกมังคุด × ทอง และหน้า A4 สำหรับส่งออก |
| `sw.js`, `manifest.webmanifest`, `icons/` | PWA |
| `database.rules.json` | กฎสิทธิ์ของฐานข้อมูล (ความปลอดภัยจริงอยู่ที่นี่) |

## ติดตั้งใช้งานจริง

1. สร้าง Firebase project ใหม่ (แผน Spark ฟรี) › เพิ่ม Web app › คัดลอกค่า config ใส่ `config.js` ส่วน `firebase`
2. Build › Realtime Database › Create database (เลือก Singapore) › แท็บ Rules › วางเนื้อหา `database.rules.json` › Publish
3. Build › Authentication › Sign-in method › เปิด Google
4. Authentication › Settings › Authorized domains › เพิ่มโดเมน GitHub Pages (เช่น `ชื่อผู้ใช้.github.io`)
5. อัปไฟล์ทั้งโฟลเดอร์ขึ้น GitHub repo › Settings › Pages › เปิดใช้งาน
6. ล็อกอินด้วยอีเมลครูใน `teacherEmails` › เพิ่มที่ปรึกษา › นำเข้ารายชื่อสมาชิก › กำหนดตำแหน่งและรอบซ้อม

ถ้าเปลี่ยนอีเมลครูคนแรก ต้องแก้ทั้ง `config.js` (`teacherEmails`) และ `database.rules.json` (ค้นหาอีเมลเดิมแล้วแทนที่ทุกจุด)

**ทดสอบก่อนเปิดใช้:** ล็อกอินจากไอคอนบนหน้าจอโฮมของ iPhone, iPad และ Android อย่างละเครื่อง ถ้านักเรียนเปิดลิงก์จาก LINE แอปจะเตือนให้เปิดใน Safari/Chrome

## ข้อควรระวัง

- repo เป็นสาธารณะ: ห้ามใส่ชื่อนักเรียนหรือข้อมูลจริงในไฟล์ใด ๆ ข้อมูลจริงอยู่ในฐานข้อมูลเท่านั้น ข้อมูลสาธิตใน `backend.js` (`seedDemo`) เป็นชื่อสมมติ
- ทุกครั้งที่แก้ไฟล์แล้วอัปขึ้นเว็บ ให้เปลี่ยนเลขรุ่น `CACHE` ใน `sw.js` (เช่น `spw-v2`) ไม่เช่นนั้นเครื่องผู้ใช้อาจยังใช้ไฟล์เก่า
- ส่งออก PDF/PNG ใช้ html2canvas และ jsPDF จาก CDN (ต้องออนไลน์ครั้งแรก) ถ้าต้องการใช้ออฟไลน์ ให้วาง `html2canvas.min.js` และ `jspdf.umd.min.js` ในโฟลเดอร์ `lib/`
- รายชื่อ DOCX ใช้ฟอนต์ TH SarabunPSK เครื่องที่เปิดต้องมีฟอนต์นี้

## โครงข้อมูล (Realtime Database)

| Path | เนื้อหา | อ่าน | เขียน |
|---|---|---|---|
| `config` | ปีการศึกษา, ที่ปรึกษา (`advisors`), รายการเครื่องดนตรี | สมาชิก, ครู | ครู |
| `teachers/{อีเมลแทนจุดด้วยจุลภาค}` | ครูที่ล็อกอินได้ | ครู, เจ้าของอีเมล | ครู |
| `members/{เลขประจำตัว}` | คำนำหน้า ชื่อ ชั้น ห้อง ประเภท สถานะ รอบซ้อม (`am`,`pm`) เครื่องดนตรี รูปย่อ | สมาชิก, ครู | ครู; เลขานุการ (เพิ่ม/แก้ แต่เปลี่ยนสถานะและรอบซ้อมไม่ได้); เจ้าตัว (เฉพาะรูป) |
| `roles/{เลขประจำตัว}` | ตำแหน่ง (`role`, `grade`) | สมาชิก, ครู | ครู |
| `skills/{เลขประจำตัว}/{เครื่องดนตรี}` | ระดับฝีมือ 1–8 | สมาชิก, ครู | ครู |
| `privateInfo/{เลขประจำตัว}` | เบอร์โทร ผู้ปกครอง | ครู, เลขานุการ, เจ้าตัว, กรรมการชั้นเดียวกัน | ครู, เลขานุการ, เจ้าตัว |
| `photos/{เลขประจำตัว}` | รูปขนาดพิมพ์ (โหลดเฉพาะตอนส่งออก) | สมาชิก, ครู | ครู, เลขานุการ, เจ้าตัว |
| `history/{id}` | ประวัติการแก้ไข เขียนได้ครั้งเดียว | ครู | สมาชิก, ครู (เพิ่มอย่างเดียว) |

การนำสมาชิกออกเป็นการเปลี่ยน `status` (`removed` / `alumni`) ไม่ลบข้อมูล ลบถาวรได้เฉพาะรายการที่ระบุเหตุผลว่า “เพิ่มผิด”

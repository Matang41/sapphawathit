# สรรพวาทิต — ระบบบริหารจัดการชมรมดนตรีไทย โรงเรียนสรรพวิทยาคม

รุ่น 3.1 — เพิ่มระบบรางวัล เกียรติบัตร คลังความรู้ เกม และคู่มือ (ดูหัวข้อ “รุ่น 3.1” ท้ายไฟล์) · รุ่น 3.0 — รองรับหลายชมรมบนฐานเดียว (สรรพวาทิต + แก้วทิพย์) ทะเบียนนักเรียนกลาง และระดับฝีมือแก้ไขได้รายชมรม

> **อัปเดตจากรุ่นก่อน ต้องทำ 2 อย่าง:** (1) อัปไฟล์ทั้งหมดขึ้น GitHub (2) คัดลอก `database.rules.json` ไปวางที่ Firebase Console › Realtime Database › Rules แล้ว Publish ใหม่ ถ้าลืมข้อ 2 แอปจะขึ้นแถบแดงเตือนครูว่า Rules เป็นรุ่นเก่า

PWA แบบ static ไม่มี build step (HTML + CSS + Vanilla JS) โครงเดียวกับระบบ Mae Sot Musicology

## หลายชมรม (รุ่น 3.0)

- ชมรมกำหนดใน `config.js` → `clubs` (รหัส ชื่อ โลโก้ สี ระดับฝีมือตั้งต้น) ข้อมูลของแต่ละชมรมเก็บแยกที่ `c/{รหัสชมรม}/…` (`spw` = สรรพวาทิต, `kt` = แก้วทิพย์)
- **ทะเบียนกลาง** `people/{เลขประจำตัว}` เก็บชื่อ ชั้น ห้อง รูป ชุดเดียว ครูติ๊กที่เมนู “ทะเบียนกลาง” ว่าใครอยู่ชมรมไหน (อยู่ได้มากกว่าหนึ่งชมรม) แก้ชื่อ/ชั้นที่ใดก็ได้ ระบบปรับให้ตรงกันทุกชมรม
- นักเรียนอ่านได้เฉพาะข้อมูลของชมรมที่ตัวเองเป็นสมาชิก (บังคับที่ Rules) คนที่อยู่สองชมรมเลือกชมรมตอนเข้า และสลับได้จากเมนู
- ครูที่ปรึกษา: อีเมลใน `teacherEmails` ดูแลทุกชมรม · ครูที่เพิ่มในหน้า “จัดการ” ของชมรมใด ดูแลเฉพาะชมรมนั้น
- การเงิน กิจกรรม การซ้อม โหวต ร้องทุกข์ ใบสมัคร ระดับฝีมือ เครื่องดนตรี ปีการศึกษา แยกกันรายชมรม
- ระดับฝีมือ: หน้า “แผนผัง” หรือ “จัดการ” → แก้ไข (หนึ่งบรรทัดต่อหนึ่งระดับ `ชื่อ | รายละเอียด`) ระบบแสดง Lv.1, Lv.2 … นำหน้าให้เอง
- ลิงก์เดียวใช้ได้ทั้งสองชมรม (`index.html`) · `kaewthip.html` เป็นทางเข้าที่เปิดชมรมแก้วทิพย์ทันทีและติดตั้งเป็นแอปไอคอนแก้วทิพย์ได้
- ขึ้นปีการศึกษาทำแยกรายชมรม คนที่อยู่สองชมรมถูกเลื่อนชั้นครั้งเดียว

### อัปเกรดจากรุ่น 2.x (ทำครั้งเดียว)

1. อัปโหลดไฟล์ทั้งหมดขึ้น GitHub
2. Firebase Console → Realtime Database → Rules → วางเนื้อหา `database.rules.json` ใหม่ทั้งหมด → Publish (ถ้าไม่ทำ แอปจะขึ้นแถบเตือนว่า Rules ไม่ใช่รุ่นล่าสุด และอ่าน/เขียนไม่ได้)
3. เข้าแอปด้วยบัญชีครู เลือกชมรมสรรพวาทิต → หน้า “จัดการ” → การ์ด “ข้อมูลจากรุ่นก่อน” → “ย้ายข้อมูล” ระบบคัดลอกข้อมูลเดิมเข้า `c/spw/` (ของเดิมไม่ถูกลบ) ตรวจแล้วค่อยกด “ลบข้อมูลชุดเก่า”

### เพิ่มชมรมที่สาม

เพิ่มรายการใน `config.js` → `clubs` และเพิ่มรหัสชมรมใน `CLUBS` ของ Rules (ส่วน `privateInfo` `photos` `people` `ctoken` ระบุรหัสชมรมไว้ตรง ๆ) แล้ว Publish Rules ใหม่

## ลองใช้ทันที (โหมดสาธิต)

ยังไม่ต้องมี Firebase: เปิด `index.html` ผ่านเว็บเซิร์ฟเวอร์ (หรืออัปขึ้น GitHub Pages) แล้วกดเข้าสู่ระบบ ระบบจะให้เลือกบัญชีสมมติ ข้อมูลเก็บในเบราว์เซอร์นั้นเท่านั้น

เมื่อใส่ค่า Firebase จริงแล้ว ยังเข้าโหมดสาธิตได้ด้วย `index.html?demo=1` และออกด้วย `?demo=0`

## ติดตั้งใช้งานจริง

1. สร้าง Firebase project ใหม่ (แผน Spark ฟรี) › เพิ่ม Web app › คัดลอกค่า config ใส่ `config.js` ส่วน `firebase`
2. Build › Realtime Database › Create database (เลือก Singapore) › แท็บ Rules › วางเนื้อหา `database.rules.json` › Publish
3. Build › Authentication › Sign-in method › เปิด Google
4. Authentication › Settings › Authorized domains › เพิ่มโดเมน GitHub Pages (เช่น `ชื่อผู้ใช้.github.io`)
5. อัปไฟล์ทั้งโฟลเดอร์ขึ้น GitHub repo › Settings › Pages › เปิดใช้งาน
6. ล็อกอินด้วยอีเมลครูใน `teacherEmails` › จัดการ › เพิ่มที่ปรึกษา › นำเข้ารายชื่อสมาชิก › กำหนดตำแหน่งและรอบซ้อม
7. เปิดกิจกรรมใดก็ได้ › สร้างใบ วก.12 › กรอกชื่อรองผู้อำนวยการและผู้อำนวยการ (ระบบจำไว้ในฐานข้อมูล ไม่อยู่ในโค้ด)

ถ้าเปลี่ยนอีเมลครูคนแรก ต้องแก้ทั้ง `config.js` (`teacherEmails`) และ `database.rules.json` (ค้นหาอีเมลเดิมแล้วแทนที่ทุกจุด)

**ตรวจก่อนใส่ข้อมูลจริง**

- ล็อกอินจากไอคอนบนหน้าจอโฮมของ iPhone, iPad และ Android อย่างละเครื่อง
- ล็อกอินเป็นนักเรียนธรรมดา 1 คน ตรวจว่าแก้ข้อมูลคนอื่น เปิดบัญชีการเงินรายการย่อย และอ่านเรื่องร้องทุกข์ของคนอื่นไม่ได้
- ลองส่งออก PDF หนึ่งครั้ง และลองให้โทรศัพท์อีกเครื่องเปิดลิงก์ใบขออนุญาตแล้วเซ็น

## ข้อควรระวัง

- repo เป็นสาธารณะ: ห้ามใส่ชื่อนักเรียน ชื่อผู้บริหาร หรือข้อมูลจริงในไฟล์ใด ๆ ข้อมูลจริงอยู่ในฐานข้อมูลเท่านั้น ข้อมูลสาธิตใน `backend.js` (`seedDemo`) เป็นชื่อสมมติ
- ทุกครั้งที่แก้ไฟล์แล้วอัปขึ้นเว็บ ให้เปลี่ยนเลขรุ่น `CACHE` ใน `sw.js` (ตอนนี้ `spw-v6`) ไม่เช่นนั้นเครื่องผู้ใช้อาจยังใช้ไฟล์เก่า
- ส่งออก PDF/PNG ใช้ html2canvas และ jsPDF จาก CDN (ต้องออนไลน์ครั้งแรก) ถ้าต้องการใช้ออฟไลน์ ให้วาง `html2canvas.min.js` และ `jspdf.umd.min.js` ในโฟลเดอร์ `lib/`
- ไฟล์ DOCX ใช้ฟอนต์ TH SarabunPSK เครื่องที่เปิดต้องมีฟอนต์นี้
- การออกใบรับเงิน/ใบเบิกเงิน การอนุมัติ การลงคะแนน และการร้องทุกข์ ต้องออนไลน์ ส่วนการเช็กชื่อทำออฟไลน์ได้แล้วส่งเมื่อมีสัญญาณ
- ไม่มีการแจ้งเตือนแบบ push (แผนฟรีไม่มีเซิร์ฟเวอร์) ตัวเลขงานค้างจะแสดงบนเมนูเมื่อเปิดแอป
- รูปหลักฐานการซ้อมเก็บในฐานข้อมูล (ราว 100–250 KB ต่อรูป) ฐานข้อมูลฟรีจุ 1 GB ควรตรวจขนาดใน Firebase Console ปีละครั้ง
- ลิงก์ใบขออนุญาตผู้ปกครองเป็นรหัสสุ่ม ใครมีลิงก์ก็เปิดอ่านและเซ็นได้หนึ่งครั้ง จึงควรส่งให้ผู้ปกครองโดยตรง และครูต้องกด “ยืนยัน” หลังตรวจชื่อและเบอร์โทร
- “ขึ้นปีการศึกษาใหม่” (หน้าจัดการ) ทำครั้งเดียวต่อปีและย้อนกลับเองไม่ได้

## เมื่อบันทึกไม่สำเร็จ

ป้ายมุมขวาบนจะเปลี่ยนเป็น “ส่งไม่สำเร็จ” แตะเพื่อดูว่ารายการใดถูกปฏิเสธและเพราะอะไร กด “คัดลอกรายละเอียด” เพื่อส่งให้ผู้พัฒนา สาเหตุที่พบบ่อยคือ Rules ในฐานข้อมูลไม่ใช่รุ่นล่าสุด ทุกครั้งที่แก้ Rules ให้เพิ่มเลข `rulesProbe` ใน `database.rules.json` และ `RULES_V` ใน `app.js` ให้ตรงกัน

## โครงข้อมูล (Realtime Database)

ข้อมูลสาธารณะ: `public/join` (สถานะเปิดรับสมัคร) · `applications/{เลขประจำตัว}` (ใบสมัครรอรับ) · รายปี `behave/{sid}/{วันจันทร์}` (ผลประเมินพฤติกรรม)

ข้อมูลข้ามปี: `config` `teachers` `members` `roles` `skills` `privateInfo` `photos` `history` `actions` `ctoken` `polls` `ballots` `griev` `alumni` `archive`

ข้อมูลรายปีอยู่ใต้ `y/{ปีการศึกษา}/`:

| Path | เนื้อหา |
|---|---|
| `att/{sid}/{วัน_รอบ}` | `p` มา · `l` สาย · `v` ลา · `a` ขาด |
| `attmeta/{วัน}/{am\|pm}` | ผู้เช็ก เวลา จำนวน ผู้ยืนยัน |
| `attphoto/{วัน}/{am\|pm}` | รูปหลักฐาน (โหลดเมื่อเปิดดู) |
| `leaves/{sid}/{id}` · `leavemark/{วัน_รอบ}/{sid}` | ใบลา (เหตุผลลับ) · สถานะที่ผู้เช็กเห็น |
| `events/{id}` · `announce/{id}` · `acks/{sid}/{id}` | กิจกรรม ประกาศ การรับทราบ |
| `forms12/{eid}/{id}` | รายชื่อ ณ วันที่ออก วก.12 |
| `bands/{id}` | ผังวง (`seats/{id}`: สมาชิก เครื่อง แถว ลำดับ) |
| `consents/{sid}/{eid}` | รหัสลิงก์ใบขออนุญาต (ตัวใบอยู่ที่ `ctoken/{รหัส}`) |
| `ledger/{id}` · `counters` · `finsum` | บัญชี เลขที่ล่าสุด สรุปให้สมาชิกอ่าน |

## แก้ไขต่อ

โมดูลใหม่เพิ่มได้โดยสร้างไฟล์ `.js` แล้วลงทะเบียนผ่าน `window.APP`: `APP.V.ชื่อหน้า = () => ({ title, body })`, `APP.NAVS.push(...)`, `APP.SUBS.push({ key, path })`, `APP.ACT.ชื่อปุ่ม = ...` แล้วเพิ่มไฟล์ใน `index.html` และ `sw.js` และเพิ่มกฎใน `database.rules.json`

## รุ่น 3.1 — ระบบรางวัล เกียรติบัตร คลังความรู้ เกม คู่มือ

**อัปเดตจากรุ่น 3.0 ต้องทำ 2 อย่าง:** (1) อัปไฟล์ทั้งหมดขึ้น GitHub (2) คัดลอก `database.rules.json` ไปวางที่ Firebase Console › Realtime Database › Rules แล้ว Publish (เลข `rulesProbe` เปลี่ยนเป็น v5 / `RULES_V = 5`)

| เมนู | ใครใช้ | ทำอะไร |
|---|---|---|
| เกียรติยศและรางวัล (`honor.js`) | ทุกคน / ครูให้รางวัล | ประกาศยกย่องบนหน้าหลัก ทำเนียบเกียรติยศรายปี เกียรติบัตรและคุณลักษณะของตัวเอง ครูกด “ให้รางวัล / ออกเกียรติบัตร” เลือกรายการ (แก้ที่ `config.js` › `awardPresets`) หรือพิมพ์เอง เลือกผู้รับหลายคนหรือพิมพ์ชื่อนอกรายชื่อ |
| คุณลักษณะอันพึงประสงค์ (ครู) | ครู | ประเมิน 8 ข้อ ระดับ 0–3 ระบบแนะนำค่าจากการซ้อม พฤติกรรมรายสัปดาห์ ระดับฝีมือ กิจกรรม ครูแก้ได้ทุกข้อ ส่งออก PDF/DOCX |
| ทะเบียนเกียรติบัตร (ครู) | ครู | เลขที่ `ก.001/ปี` รันอัตโนมัติ ค้นหา ดูซ้ำ/พิมพ์ซ้ำ ยกเลิกพร้อมเหตุผล ส่งออก |
| คลังความรู้ (`library.js`) | ทุกคน / ครูอัปโหลด | ไฟล์ไม่เกิน ~700 KB เก็บในฐานข้อมูล (รูปย่อให้อัตโนมัติ) หรือใส่ลิงก์ Drive/YouTube สำหรับไฟล์ใหญ่ |
| เกม (`games.js`) | ทุกคน | ยังว่าง — เพิ่มเกมที่ `config.js` › `games` (ไฟล์ HTML ใน `games/`) หรือ `APP.GAMES.push(...)` |
| คู่มือการใช้ / เวอร์ชันและรายการอัปเดต (`about.js`) | ทุกคน | คู่มือเพิ่มได้ในแอป (ครู) หรือที่ `config.js` › `manual` · รายการอัปเดตแก้ที่ `config.js` › `version`, `versionDate`, `changelog` |

ข้อมูลใหม่ในฐานข้อมูล (ใต้ `c/{ชมรม}/`): `awards` · `certs` (ครูเท่านั้น) · `certidx/{sid}` (สำเนาเกียรติบัตรให้เจ้าตัวอ่าน) · `library` · `libfiles` · `config/libCats` · `config/manual` · `y/{ปี}/traits/{sid}` · `y/{ปี}/certno`

## รุ่น 3.2 — ระบบประเมินรวม ข้อมูลชมรม โหมดผู้ปกครอง ลายเซ็นครู

**อัปเดตจากรุ่น 3.1:** อัปไฟล์ทั้งหมด (รวม `icons/rules-poster.jpg`) แล้ววาง `database.rules.json` ใหม่ที่ Firebase Console › Rules › Publish (`rulesProbe` v6 / `RULES_V = 6`)

- **ประเมินรวม** (`behave.js`): แท็บ รายสัปดาห์ · คุณลักษณะ · สรุปรายคน ระดับ 4 ขั้น หมวดแก้ได้ที่ `config.js` › `traitGroups` สัดส่วนที่ `behaveWeights` · ความตั้งใจ 1–3 ให้ในหน้า “การซ้อม” (`y/{ปี}/focus`)
- **ข้อมูลชมรม** (`clubinfo.js`): เนื้อหาตั้งต้นที่ `config.js` › `clubInfo` ครูเพิ่ม MOU/กฎในแอปได้ (เก็บที่ `public/info`) สมาชิกกดยอมรับ (`y/{ปี}/acks/{sid}/rules-{ver}`) ใบสมัครผ่านลิงก์ต้องกดยอมรับ (เก็บที่ `applications/{sid}/accept` → `members/{sid}/accept`)
